# 리뷰 워크트리 명시 등록 구현 계획

**Goal:** 부모 폴더에서 시작한 세션에서도 명시 등록한 중첩 워크트리의 수정·커밋을 Stop 리뷰에 포함한다.

**Spec:** 사용자 선택 1번. 세션에 등록한 작업 경로만 추가 검사하며 Git의 모든 워크트리를 자동 편입하거나 누락 경고하지 않는다. 기존 현재 저장소·바로 하위 저장소 감지는 유지한다.

**Architecture:** 시작 훅의 작업 폴더 안에 세션별 등록 목록을 보관한다. `review_hook.py register` 명령은 `git worktree list --porcelain -z`로 대상 루트를 검증하고 수정 전 스냅샷을 확보한다. Stop은 기존 감지 범위와 등록 목록을 합쳐 검사한다. 등록 목록은 세션 동안 유지하고 스냅샷은 사용자 턴마다 갱신한다.

**Tech Stack:** Python 3.6+, Git, unittest. 임시 파일·테스트 저장소는 프로젝트 안에 둔다.

## 작업과 검증

- [x] 테스트: 부모 실행 → 중첩 워크트리 등록 → 수정·커밋 → Stop의 `base_head`와 변경 파일 검증. 기존 구현에서 실패 확인.
- [x] 테스트: 재등록 시 기준 보존, 스냅샷 누락·손상·접근 실패, 다른 세션/턴 격리, 미등록 워크트리 제외, 특수문자 경로, 다음 턴 기준 갱신.
- [x] 구현: 세션 등록 상태와 CLI, 등록 시 Git 경로 검증, 시작 훅의 등록 안내, Stop의 등록 경로 처리 및 오류 격리.
- [x] 문서: README와 SKILL에 수정 전 등록 명령, 성공 확인, 늦은 등록으로 기준 복구 금지, 감지 실패 보고를 명시.
- [x] 검증: 전체 플러그인 unittest, shell 문법 및 JSON 검사, `git diff --check`, 독립 코드 리뷰와 스킬 적용 시뮬레이션.

## 검토 초점

- 같은 턴의 재등록은 기준과 리뷰 요청 기록을 덮어쓰지 않는다.
- 등록 실패 후 Stop에서도 해당 경로를 조용히 제외하지 않는다.
- 시작 기준이 없으면 현재 HEAD나 현재 내용으로 뒤늦게 재생성하지 않는다.
- 다른 세션의 워크트리는 등록 검증용 Git 목록에 있어도 리뷰 대상이 아니다.
- 등록/수정은 순차 실행하며, 훅 cwd를 세션 상태의 기준 폴더로 사용한다.

## 검증 결과

- 기존 구현에서 등록 관련 회귀 테스트 2건이 실패했고, 최종 전체 unittest 55건이 통과했다.
- 시작 안내는 모델에게 전달되는 `hookSpecificOutput.additionalContext`를 사용한다.
  [공식 훅 문서](https://learn.chatgpt.com/docs/hooks#userpromptsubmit)로 형식을 확인했으며,
  출력 형식 검사와 출력된 명령을 Bash에서 실행하는 테스트도 실패→통과를 확인했다.
- 전체 shell 문법·플러그인/hook JSON 검사 및 `git diff --check`가 통과했다.
- 독립 코드 리뷰에서 추가 P1/P2 지적이 없었고, 문서 시뮬레이션에서 수정 전 등록,
  늦은 등록 금지, 재등록, 다른 세션 제외, 사용자 결정 대기를 확인했다.
- 실제 Git 저장소·워크트리와 훅 명령의 입출력을 검증했다. 설치된 Codex의 실세션에서
  자동 후속 리뷰까지 실행한 것은 아니다. 커밋·배포는 수행하지 않았다.

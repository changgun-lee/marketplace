# gpt-review-toolkit

Codex가 작업을 마칠 때 변경 파일을 네 분야의 서브에이전트로 리뷰하고 중요도순으로 보고합니다.
**보고 전용**이며 코드·주석·테스트를 자동 수정하지 않습니다.

## 설치

Python 3.6 이상, Git, 플러그인 훅과 서브에이전트를 지원하는 Codex 로컬 환경이 필요합니다.
별도 API 키나 고정 GPT 모델을 설정하지 않고 현재 Codex의 모델 설정을 따릅니다.

저장소 루트에서 마켓플레이스를 추가한 뒤 플러그인을 설치합니다.

```bash
codex plugin marketplace add .
codex plugin add gpt-review-toolkit@gilchris-market
```

Codex 데스크톱의 플러그인 목록에서 `gilchris-market`을 선택해 설치할 수도 있습니다.
설치 후 **훅 설정을 검토하고 신뢰**해야 자동 실행됩니다. 설치만으로 훅이 신뢰되지는 않습니다.
새 대화 또는 다음 사용자 요청부터 시작 스냅샷을 기록합니다.

이 저장소의 `.claude-plugin/marketplace.json`은 Codex가 지원하는 호환 마켓플레이스입니다.
이 플러그인 자체는 `.codex-plugin/plugin.json`을 사용하는 **Codex용**입니다.
훅 포함 플러그인은 수동 설치 배포용이며 공개 플러그인 디렉토리 제출 대상이 아닙니다.

## 동작

1. `UserPromptSubmit`에서 작업 시작 시 파일 내용의 해시와 실행 비트를 기록합니다.
2. `Stop`에서 시작 상태와 비교합니다. 변경이 없으면 아무 리뷰도 요청하지 않습니다.
3. 변경이 있으면 Codex에 리뷰 스킬 실행을 요청합니다. 주석 정확성, 사용자 의도 반영,
   테스트 충분성, 성능에 각각 별도 서브에이전트를 사용합니다.
4. 모두 취합해 중복 지적을 합치고 P0(치명적) → P1(높음) → P2(보통) → P3(낮음)으로 보고합니다.
   각 지적에는 파일 위치, 근거, 영향, 권장 수정이 포함됩니다.
5. 요구사항별 반영 여부와 미검토 범위도 보고합니다. 보고 후 종료합니다.

한 줄 변경도 대상입니다. 새 파일, 삭제, 실행 비트 변경, staged 변경, 턴 중 커밋한 변경도
포함합니다. 이름 변경은 이전 경로 삭제와 새 경로 추가로 표시합니다. 확장자로 필터링하지 않습니다.
기존 미커밋 파일이 그대로 남아 있거나 staging만 달라졌다면 리뷰하지 않습니다.
같은 턴의 동일 변경 요청과 Stop 훅의 자동 후속 턴은 반복 실행하지 않습니다.
이 상태는 **리뷰 요청 기록**이며, 리뷰 완료를 보장하는 기록이 아닙니다.

수동 리뷰는 Codex에서 `gpt-review-toolkit`의 `review` 스킬을 지정해 요청할 수 있습니다.
자동 훅의 입력이 없는 수동 호출은 별도 범위를 지정하지 않으면 현재 staged·unstaged·untracked
변경을 검토합니다. 자동 리뷰가 중단되거나 분야별 실행이 실패했을 때도 수동 재실행할 수 있습니다.

## 검토 범위와 상태 파일

- 자동 감지는 현재 작업 디렉토리가 속한 Git 저장소를 대상으로 합니다.
- Git 추적 파일과 Git ignore에 걸리지 않는 새 파일을 확인합니다. 서브모듈 내부와 별도 하위
  저장소는 자동으로 순회하지 않습니다. 서브모듈 등 제외 항목은 리뷰 입력에 기록합니다.
- 시작 시 감지한 경로는 ignore나 index 등록이 바뀌어도 실제 내용으로 비교합니다.
  반대로 ignore 해제로 처음 감지된 파일은 새 파일과 구분할 시작 원문이 없으므로,
  생성 시점이나 이번 턴의 변경분을 단정하지 않고 검토 한계로 표시합니다.
- 사용자나 다른 프로세스가 같은 턴에 변경한 파일도 감지될 수 있습니다. 파일 변경만으로
  작성자를 판별하지 않으며 리뷰 에이전트는 대화의 작업 범위와 대조합니다.
- 상태는 저장소 안 `.gpt-review-toolkit/`에 세션별로 보관합니다. 자체 `.gitignore`로 Git에서
  제외하며 worktree에서도 외부 Git 디렉토리에 쓰지 않습니다. 세션별 최신 상태를 덮어씁니다.
- 최초 스냅샷은 파일 내용을 읽어 해시를 계산합니다. 이후 inode·크기·mtime·ctime·모드가
  같은 파일의 해시는 재사용합니다. 매우 큰 저장소에서 훅 제한 시간(30초)을 넘으면
  Codex의 훅 오류가 표시될 수 있습니다.
- 기존 미커밋/새 파일의 변경 전 UTF-8 텍스트는 파일당 1 MiB, 전체 4 MiB까지 보관합니다.
  바이너리나 제한 초과로 변경 전 원문을 보관하지 못한 경우 검토 한계로 표시합니다.
  그 외 추적 파일은 시작 시점 커밋을 변경 전 기준으로 사용합니다.
- 상태에는 변경 전 소스가 포함될 수 있습니다. 불필요해지면 대화가 끝난 뒤 해당 저장소의
  `.gpt-review-toolkit/` 디렉토리를 삭제할 수 있습니다.
- Git 저장소가 아니거나 시작 상태가 없거나 상태 읽기에 실패하면 감지 실패를 알립니다.
  해당 경우를 “변경 없음” 또는 “리뷰 통과”로 보고하지 않습니다.
- Plan 모드에서는 자동 리뷰를 요청하지 않습니다. 서브에이전트 실행에 실패한 분야는
  미검토로 보고하고, 동시 실행 한도가 작으면 순차적으로 나머지 분야를 실행합니다.
- 사용자 결정 질문에 대한 대기가 프로젝트 규칙상 필요하면 리뷰도 보류합니다.
  이때는 도구 호출 없이 기존 질문을 유지하며, 답변 후 필요하면 수동 리뷰를 요청합니다.

## 로컬 검증

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s plugins/gpt-review-toolkit/tests -v
jq empty plugins/gpt-review-toolkit/.codex-plugin/plugin.json plugins/gpt-review-toolkit/hooks/hooks.json
```

테스트는 이 프로젝트 하위의 임시 Git 저장소를 만들고 정리합니다.
Codex에 설치한 뒤에는 한 줄 수정 요청과 파일을 수정하지 않는 질문을 각각 실행해,
전자는 네 분야 리뷰 보고로 이어지고 후자는 추가 리뷰를 요청하지 않는지 확인합니다.
